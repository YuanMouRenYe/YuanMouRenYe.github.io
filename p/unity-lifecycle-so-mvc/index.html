Unity 入门最容易背串的三件事：生命周期函数的执行顺序、ScriptableObject 到底解决什么问题、以及为什么小项目也该有个轻量的 MVC。

1. Unity生命周期函数

1. 初始化阶段（仅执行一次）
Awake
  • 调用时机：物体被实例化 / 场景加载时立即调用，只要物体处于激活状态，无论脚本是否启用都会执行。若物体创建时是未激活状态，Awake 会延迟到物体第一次激活时调用。
  • 执行次数：整个生命周期仅 1 次
  • 核心用途：获取自身组件、初始化内部数据、单例赋值、注册内部事件
  • 面试关键点：场景中所有物体的 Awake 会全部执行完毕，才会开始执行所有物体的 Start，因此 Awake 中获取其他物体的组件是安全的。
OnEnable
  • 调用时机：脚本组件从禁用→启用、GameObject 从非激活→激活时调用，可多次触发。
  • 执行次数：每次激活 / 启用都会调用一次
  • 核心用途：注册全局事件、订阅消息、对象池取出时重置状态、启动协程
  • 对应你的项目：对象池取出物体 SetActive (true) 会触发，子弹、状态的生命周期重置逻辑放在这里最合适。
Start
  • 调用时机：脚本启用且物体激活的前提下，第一次 Update 执行之前调用，仅执行 1 次。
  • 执行次数：整个生命周期仅 1 次
  • 核心用途：初始化外部依赖、获取其他物体引用、配置初始参数
  • 面试关键点：Start 一定在 Awake 之后、Update 之前执行，适合写依赖其他物体的初始化逻辑。
2. 物理阶段（固定频率执行）
FixedUpdate
  • 调用时机：以固定时间间隔（默认 0.02 秒，可在 Project Settings 中修改）重复调用，和游戏帧率无关，帧率低时一帧会调用多次，帧率高时多帧调用一次。
  • 执行频率：固定时间步长，和物理引擎同步
  • 核心用途：所有 Rigidbody 物理运算、力的施加、移动同步、碰撞检测逻辑
  • 对应你的项目：角色带位移的移动、怪物 AI 的物理判定、带刚体的子弹运动，必须放在这里保证不同设备上物理表现一致。
碰撞 / 触发回调

OnTriggerEnter/Stay/Exit、OnCollisionEnter/Stay/Exit

  • 调用时机：物理引擎计算完成后、FixedUpdate 结束前调用，属于物理阶段的收尾。
  • 核心用途：处理伤害判定、拾取、碰撞反应
  • 对应你的项目：武器碰撞盒的打击判定、技能范围触发，都在这个阶段执行。
3. 游戏逻辑阶段（每帧执行）
Update
  • 调用时机：每帧执行一次，执行间隔随帧率波动，是最核心的逻辑更新入口。
  • 执行频率：和帧率完全绑定，一帧一次
  • 核心用途：玩家输入处理、状态机逻辑更新、非物理类移动、计时器、UI 更新
  • 对应你的项目：玩家输入检测、状态机枚举更新、普通逻辑帧更新，全部放在这一层。
4. 动画与后置更新阶段
LateUpdate
  • 调用时机：所有物体的 Update 全部执行完毕后，统一执行所有 LateUpdate，一帧一次。
  • 核心用途：相机跟随、动画矫正、后置位置修正（保证目标位置已更新完成）
  • 面试关键点：它的核心价值是「所有前置逻辑都跑完了再执行」，避免相机跟随出现抖动、位置不同步。
5. 渲染与 GUI 阶段
  • OnWillRenderObject：物体即将被渲染前调用
  • OnRenderImage：屏幕后处理特效专用
  • OnGUI：IMGUI 绘制，每帧调用多次（事件驱动），项目开发极少使用
  • WaitForEndOfFrame：协程专用，所有渲染、GUI 完成后恢复，用于截图等帧末操作
6. 销毁与卸载阶段
OnDisable
  • 调用时机：脚本被禁用、GameObject 被设为未激活、物体销毁前都会调用，可多次触发。
  • 执行次数：每次禁用 / 失活都会调用一次
  • 核心用途：取消事件订阅、停止协程、清空计时器、对象池回收时清理状态
  • 面试关键点：事件解绑必须放在 OnDisable 而非 OnDestroy，否则物体禁用时不会解绑，会造成内存泄漏和空引用。
OnDestroy
  • 调用时机：物体被销毁（Destroy）、场景卸载时调用，整个生命周期仅 1 次。
  • 执行次数：仅 1 次
  • 核心用途：释放持久资源、移除全局注册、清理非托管数据
OnApplicationQuit
  • 调用时机：应用程序退出时调用，所有物体销毁前执行
  • 核心用途：存档、释放全局资源、断开网络连接
对比项UpdateFixedUpdateLateUpdate
执行频率随帧率波动，一帧一次固定时间步长，与帧率无关一帧一次，所有 Update 之后
时间尺度Time.deltaTimeTime.fixedDeltaTimeTime.deltaTime
核心用途输入、逻辑、状态机、UI物理运算、刚体移动、碰撞判定相机跟随、动画后置修正
对应项目状态机逻辑更新、输入检测角色物理移动、子弹飞行相机跟随、动画位置矫正

2. Script ableObject

SO

Script ableObject，继承自UnityEngine.ScriptableObject 的资源，可以像预制体和材质一样，保存在项目的Assets文件夹中，成为一个文件

核心作用：

把“数据”从逻辑代码中抽离出来，编程可以独立的可配置资源

作用

常用于配置游戏数据，技能Buff设计，事件通道

优点

1.内存优化，节省冗余：多个敌人使用同一份数据（比如“哥布林属性”），内存中只存在一份 SO 实例，而不是每个敌人身上挂一个重复脚本和一堆字段。

  1. 脱离场景，独立管理：SO 是项目资产，不依赖任何场景。即使场景被删除，数据依然保留，可以跨场景调用，也方便版本控制。

  2. 实时热重载与快速迭代：在运行模式下修改 SO 的数值，停止运行后修改仍然保留（这是很多开发者最爱的特性）。可以边运行边调参数，调好后数值不丢失。

  3. 引用强类型，不易出错：技能 SO 可以直接引用音效 SO、图标 Sprite 等。拖动引用比写字符串路径更安全。

缺点

  1. SO 不是 GameObject，无法像 MonoBehaviour 那样拥有 Transform、Collider 等组件，所以不能直接在物体上挂载组件。

  2. 无法绑定 UI 事件：按钮的 onClick 等事件只能指向场景中挂载了脚本的对象，不能直接指向 SO（需要中间脚本）。

  3. 容易产生大量小文件：如果不加节制（比如每一把武器、每一个敌人类型都做一个 SO），项目里会多出成百上千个 .asset 文件，管理起来很麻烦。

  4. 数据修改即全局影响：多个对象共享同一个 SO，若在运行时被代码修改了数据，所有使用该 SO 的对象都会受到影响。虽然提供了运行时复制机制（Instantiate），但会增加复杂度。

  5. 引用关系需要手动维护：SO 之间的引用如果丢失（移动文件等），需要逐个手动修复，大规模重构时可能较痛苦。

  6. 不适合频繁更改的动态数据：例如角色实时血量、当前位置等运行时状态，用普通变量就好，用 SO 反而不合适。

// GameEventSO.cs
using UnityEngine;
using UnityEngine.Events;

[CreateAssetMenu(menuName = "Events/Game Event")]
public class GameEventSO : ScriptableObject
{
    // 可以携带参数的事件（传一个 GameObject 表示死者）
    [System.Serializable]
    public class UnityGameObjectEvent : UnityEvent<GameObject> { }

    public UnityGameObjectEvent OnRaise;

    public void Raise(GameObject sender)
    {
        OnRaise?.Invoke(sender);
    }
}

// PlayerHealth.cs
using UnityEngine;

public class PlayerHealth : MonoBehaviour
{
    public GameEventSO playerDiedEvent;  // 引用 .asset

    public int health = 100;

    public void TakeDamage(int damage)
    {
        health -= damage;
        if (health <= 0)
        {
            Die();
        }
    }

    private void Die()
    {
        // 触发事件，把自身传出去
        playerDiedEvent.Raise(gameObject);
        // 可以在此处播放死亡动画等自身逻辑
    }
}

// AudioManager.cs
using UnityEngine;

public class AudioManager : MonoBehaviour
{
    public GameEventSO playerDiedEvent;

    private void OnEnable()
    {
        playerDiedEvent.OnRaise.AddListener(OnPlayerDied);
    }

    private void OnDisable()
    {
        playerDiedEvent.OnRaise.RemoveListener(OnPlayerDied);
    }

    private void OnPlayerDied(GameObject player)
    {
        Debug.Log("播放死亡音效");
        // AudioSource.PlayClipAtPoint(...);
    }
}

SO事件相对于传统的事件系统，不需要手动的取消订阅事件，直接写在OnEnable()和 OnDisable()方法中能够在挂载物体销毁时，引用转为空

3. MVC架构

核心是通过明确的职责划分，解决代码混乱，维护困难的问题

  1. 数据模型Model：负责存储数据和处理数据逻辑
  2. 视图View：负责接收用户操作和展示数据
  3. 控制器Controller;链接Model和View，当View收到用户操作，Controller就转发指令给Model修改数据，当Model发生改变Controller就通知View更新界面

using UnityEngine;
using UnityEngine.UI;
using TMPro;

public class Counter : MonoBehaviour
{
    // 计数数据
    private int count = 0;

    // Unity UI Component
    [SerializeField] private TextMeshProUGUI countText;
    [SerializeField] private Button addButton;

    private void Start()
    {
        addButton.onClick.AddListener(OnAddButtonClicked);
        UpdateCountDisplay(); // 初始化显示
    }

    // 修改计数数据
    public void AddCount(int value)
    {
        count += value;
        UpdateCountDisplay();
    }

    // 按钮点击调用
    private void OnAddButtonClicked()
    {
        AddCount(1);
    }

    // 更新文本显示
    private void UpdateCountDisplay()
    {
        countText.text = $"Count: {count}";
    }
}

using System;

public class CounterModel
{
    // 计数数据
    private int count = 0;

    // 数值变化事件
    public event Action<int> OnCountChanged;

    // 修改计数数据
    public void AddCount(int value)
    {
        count += value;
        OnCountChanged?.Invoke(count); // 触发事件
    }
}

using UnityEngine;

public class CounterController : MonoBehaviour
{
    [SerializeField] private CounterView view;    // 视图引用
    private CounterModel model;                   // 数据模型

    private void Start()
    {
        // 初始化 Model
        model = new CounterModel();
        // 初始化 View
        view.Initialize(OnAddButtonClicked);
        // Model 数据变化事件绑定
        model.OnCountChanged += view.UpdateCountDisplay;
        // 初始化显示
        view.UpdateCountDisplay(model.Count);
    }

    // 点击按钮
    private void OnAddButtonClicked()
    {
        model.AddCount(1); // 计数加1
    }
}
