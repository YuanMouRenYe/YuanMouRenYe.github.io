Unity 多人联网：Mirror 与 Netcode for GameObjects（NGO）

  • 核心模型相同：服务器权威 + 状态同步，客户端发请求、服务器改真相再下发。

选型与共同点

维度MirrorNGO (Netcode for GameObjects)
来源社区（原 UNET 分支）Unity 官方包
包名导入 Mirror 资源 / UPMcom.unity.netcode.gameobjects
网络实体NetworkIdentityNetworkObject
行为脚本基类NetworkBehaviourNetworkBehaviour
总控NetworkManager（勿挂在 NetworkIdentity 上）NetworkManager（全场景唯一）
状态同步变量[SyncVar]NetworkVariable<T>
远程调用[Command] [ClientRpc] [TargetRpc][Rpc(SendTo.Server)] 等
Transform 同步NetworkTransform（Mirror 组件）NetworkTransform（NGO 组件）
传输层Telepathy / KCP 等（常 TCP+UDP 组合）Unity Transport（UTP，偏 UDP）
公网联机需自建 / Relay 第三方Unity Relay + Lobby 官方链路
学习资料项目内 Mirror 笔记、社区多官方文档、Multiplayer Tools

共同原则

  1. 每个联网对象有权威端（通常是 Server）。
  2. 客户端只发指令（RPC），玩法判定在服务器。
  3. 持久状态用同步变量（SyncVar / NetworkVariable），持续位置用 NetworkTransform。
  4. 场景中通常只有一个激活的 NetworkManager。

客户端 / 服务器 / Host

Mirror 与 NGO 都不是固定两个 exe，而是通过打包方式 + 启动 API 区分角色。

形态说明MirrorNGO
客户端渲染、输入、发 RPC；不做权威判定StartClient()StartClient()
专用服务器无头、无渲染；权威逻辑StartServer() + Headless BuildStartServer() + Dedicated Server Build
Host同进程兼 Server + ClientStartHost()StartHost()
能力MirrorNGO
是否服务器isServerIsServer（Host 也为 true）
是否客户端isClientIsClient（Host 也为 true）
是否 HostisServer && isClientIsHost
是否本地拥有者isOwned / hasAuthority（版本用语）IsOwner
已入网netIdentity != null 等IsSpawned

Host 注意：写逻辑时用 IsServer / isServer 做玩法判定，不要只用 IsClient，否则 Host 会漏逻辑。

连接是如何建立的

通用流程（二者逻辑一致）

Mirror：传输与握手（你的笔记要点）

  1. 传输层：Mirror 通过 Transport 抽象使用 TCP / UDP（默认封装，一般不直接写 Socket）。
    • TCP：连接、鉴权、关键可靠消息。
    • UDP：位置等实时数据（上层可加重传）。
  2. 服务器：StartServer() / StartHost() → 绑定 0.0.0.0:端口 → 监听。
  3. 客户端：StartClient(address, port) → 向目标 IP 发起连接。
  4. TCP 三次握手：SYN → SYN+ACK → ACK（Mirror Transport 自动完成）。
  5. 应用层握手：版本协商、可选身份验证 → 成功则同步房间/玩家列表。
  6. NetworkManager：连接全流程入口；回调如 OnServerConnect、OnClientConnected。
Host vs 专服区别
Headless Server独立进程监听；客户端连 IP:Port
Host无独立服程序；StartHost() 本地同时开服+客；其他客户端连 Host 的局域网 IP

Mirror.NetworkManager 注意

  1. 每场景仅一个激活的 NetworkManager（单例）。
  2. 不要把 NetworkManager 挂在带 NetworkIdentity 的对象上（场景加载时可能被禁用）。
  3. 一个节点树只允许一个 NetworkIdentity，挂在父节点；父链上不能再有 Identity。

NGO：传输与鉴权

项说明
Unity Transport默认 UTP（UDP），在 NetworkManager 选 Transport
连接StartServer / StartHost / StartClient，地址端口在 Transport / NetworkConfig
鉴权ConnectionApproval = true + ConnectionApprovalCallback
公网Unity Relay，客户端无需主机公网 IP
断开NetworkManager.Singleton.Shutdown()

修饰符 / 执行上下文（Mirror 独有语法）

Mirror含义
[Server]仅服务器执行；客户端调用会警告
[ServerCallback]仅服务器执行；客户端调用不警告（常用于 Update 里包一层）

同步变量对照

Mirror [SyncVar]NGO NetworkVariable<T>
谁改仅 Server 改字段常用 WritePermission.Server
客户端只读，自动同步.Value 读，Server 写
变化回调[SyncVar(hook = nameof(OnHpChanged))]OnValueChanged += ...
Hook 执行端在客户端，收到服务器同步后触发各端订阅，在值变化时触发
UI 更新在 hook 里改 UI（客户端）在 OnValueChanged 里改 UI

为什么本地直接改 UI 不会同步给别人？
UI 只是本机表现；要让所有人看到名字/颜色，必须 Command/RPC → 服务器改 SyncVar/NetworkVariable → 自动同步到所有客户端 → hook/OnValueChanged 更新 UI。

public NetworkVariable<FixedString64Bytes> PlayerName = new(
    default,
    NetworkVariableReadPermission.Everyone,
    NetworkVariableWritePermission.Server);

[Rpc(SendTo.Server)]
void SubmitNameRpc(FixedString64Bytes name)
{
    PlayerName.Value = name;
}

public override void OnNetworkSpawn()
{
    PlayerName.OnValueChanged += (_, newVal) => nameText.text = newVal.ToString();
}

客户端 / 服务器 / Host

Mirror 没有固定的“客户端 exe / 服务器 exe”两套工程，靠打包方式 + 启动 API 区分角色。

客户端打包
  • 可独立运行的游戏本体
  • 负责：输入、渲染、音效
  • 向服务器同步本地状态（位置、操作），接收服务器下发的全局状态
  • 不参与权威判定（血量、胜负等由服务器算）
服务器形态
1. 无头专用服务器（Headless Server）
项说明
形态无图形界面的独立可执行程序
内容仅网络逻辑 + 权威玩法；不加载渲染/UI
职责管理连接、鉴权、碰撞/得分/血量、全局状态同步
打包Build Settings 勾选平台 + Mirror Headless Server
2. Host（客户端兼服务器）
项说明
形态复用同一客户端程序，运行时 StartHost()
Host 端既渲染操作，又在本地跑服务端逻辑
其他客户端连 Host 的 IP:Port
本地通信Host 的 Client 与内置 Server 走进程内通道，延迟更低
适用原型、局域网、小规模房间

传输层（Mirror Transport）
协议用途
TCP可靠连接、鉴权、关键状态消息

步骤概览
  sequenceDiagram
    participant S as Server
    participant C as Client
    S->>S: 1. 绑定 0.0.0.0:端口，StartServer/Host 监听
    C->>S: 2. StartClient，指定 IP:Port
    Note over C,S: 3. TCP 三次握手（Transport 自动）
    C->>S: 4. 应用层握手（版本、可选鉴权）

  1. 服务器启动：绑定 IP（常用 0.0.0.0）+ 端口（如 7777），防火墙放行。
  2. 客户端连接：知晓服务器地址（局域网 IPv4 / 公网 IP 或域名 + 端口映射）。
  3. TCP 三次握手：SYN → SYN+ACK → ACK。
  4. Mirror 应用层握手：协议版本、可选密码/防作弊；失败则断开。
  5. 回调：OnServerConnect / OnClientConnected 等做业务逻辑。

SyncVar 与 UI 同步

SyncVar 规则
  • 标记需要同步的字段，仅服务器可改值
  • 客户端自动收到更新
  • [SyncVar(hook = nameof(OnXxxChanged))]：值变化时调用 hook

重要：hook 在客户端收到同步后执行（用于更新 UI），不是在服务器上执行。

名字 / 颜色同步流程

    participant O as Owner Client
    participant S as Server

using Unity.Netcode;
using UnityEngine;

namespace HelloWorld
{
    public class HelloWorldPlayer : NetworkBehaviour
    {
        // 默认：Server 写，所有人读
        public NetworkVariable<Vector3> Position = new NetworkVariable<Vector3>(
            Vector3.zero,
            NetworkVariableReadPermission.Everyone,
            NetworkVariableWritePermission.Server);

        public override void OnNetworkSpawn()
        {
            Position.OnValueChanged += (_, newVal) => transform.position = newVal;
            if (IsOwner) Move();
        }

        public override void OnNetworkDespawn()
        {
            Position.OnValueChanged -= (_, newVal) => transform.position = newVal;
        }

        public void Move() => SubmitPositionRequestRpc();

        [Rpc(SendTo.Server)]
        private void SubmitPositionRequestRpc(RpcParams rpcParams = default)
        {
            var randomPosition = GetRandomPositionOnPlane();
            transform.position = randomPosition;
            Position.Value = randomPosition; // 仅 Server 可写
        }

        static Vector3 GetRandomPositionOnPlane()
        {
            return new Vector3(Random.Range(-3f, 3f), 1f, Random.Range(-3f, 3f));
        }
    }
}

生产环境更推荐用 OnValueChanged 更新 Transform，而不是每帧在 Update 里赋值（减少无谓逻辑）。

同步方案选型

方式优点缺点适用
NetworkTransform自动插值、省代码带宽随物体数量增角色、可拾取物、大部分动态物体
NetworkVariable精确、可订阅变化需自己处理表现血量、弹药、枚举状态、回合数
RPC瞬时事件、无需持久状态不保证顺序、不能当存档开枪音效、一次性技能、聊天
手动 RPC + Transform完全自定义易出 desync、要写插值特殊同步规则

void ApprovalCheck(
    NetworkManager.ConnectionApprovalRequest request,
    NetworkManager.ConnectionApprovalResponse response)
{
    string payload = System.Text.Encoding.UTF8.GetString(request.Payload);
    bool approved = payload == "expected_token";
    response.Approved = approved;
    response.CreatePlayerObject = approved;
    response.Pending = false;
}
