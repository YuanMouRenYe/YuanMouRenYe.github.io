知识点六、事件与委托的区别

事件不能在类外部直接赋值，但是可以加减其中的函数

事件不能在类外部直接调用，但是通过在类中封装好调用的函数

事件只能作为成员变量来存在于类中，不能作为临时变量

知识点七、匿名函数的配合使用脱离委托和事件是不会使用匿名函数的

匿名函数的基本语法：

匿名函数可以作为函数的参数也可以作为返回值，同时，匿名函数也不可以直接从事件中-=，因为没有注册的具体名字，无法单独移除，只能直接清除整个事件，直接把整个事件赋值为null，C#：Lambda 和匿名方法功能几乎一样，Lambda 更强（支持异步、表达式树）

在使用匿名函数或者lambda表达式时会产生闭包

闭包的含义：内层的函数可以引用包含在他外层的函数的变量，即使是外层函数的执行已经终止也不会被回收

栈

知识点一、Stack的本质

栈是一种C#封装好的一种数据结构，本质是object[]数组只是封装了特殊的存储规则·

栈是以底层容器完成其所有的工作，对外提供统一的接口，底层容器是可插拔的（也就是说我们可以控制使用哪种容器来实现栈的功能）。

先存入的数据后获取，后存入的数据先获取（遵循先入后出的原则）

知识点二、Stack的申明

需要引用using System.Collections

知识点三、增取查改

增（Push）

压栈(只能一个一个放)

1

stack.Push(1);

取（Pop）

栈中不存在删除的概念，只有弹栈，直接弹出顶部的

1

stack.Pop();

查（Peek,Contains）

无法查看指定位置的元素，只能查看栈顶的内容（没有提供相应的索引 器）（Peek）

查看元素是否存在于栈中（Contains）

改（Clear）

无法直接更改某一个指定元素，所以只能清空所有元素进行压栈和弹栈。

知识点四、遍历

这里提出一个问题他既然都可以找出来他的数量了为什么不能通过索引访问用for来遍历

栈是后进先出的受限线性结构，标准定义只允许在栈顶进行 Push/Pop/Peek 操作，C# 的 Stack类也通过语法封装强制了这一规则，不提供索引器，目的是保证栈的使用规范。所以不能用for 循环遍历

  • 可以遍历长度（Count）

  • 可以用foreach来遍历（遍历出来的顺序是从栈顶到栈底）

  • 也可以强制转换为object数组在进行遍历，顺序也是从栈顶到栈底，（stack.ToArray（））

    到这里就可以用for遍历了

迭代器

迭代器（iterator）有时又称为光标（cursor）是程序设计的软件设计模式 迭代器模式提供一个方法顺序访问一个聚合对象中的各个元素而不暴露其内部的标识

从表现效果上来看是可以在容器对象上遍历访问的接口设计人员无需关系容器对象的内存分配的实现细节 可以用foreach便利的类 都是实现了迭代器的

主要有两种方式：

  1. 传统方式：通过继承两个接口，实现四个方法
  2. 用语法糖：yield return 去返回内容，只继承一个接口

知识点一、标准迭代器的实现方法

  1. 关键接口：IEnumerator,IEnumerable 命名空间：using System.Collections; 可以通过同时继承IEnumerable 和IEnumerator实现其中的方法
  2. 如果想要在自己类中实现迭代器：需要一个名字为GetEnumerator返回值是IEnumerator的方法
  3. 继承接口只是为了便于书写
  4. foraech的本质：
    1. 获取in后面对象的IEnumerator，调用GetEnumerator方法来获取
    2. 执行IEnumerator对象中的MoveNext方法
    3. 只要得到了MoveNext返回值是true就回去得到Current，然后赋值到item
    4. 在完成了一轮之后，光标节点需要重置调用Reset函数一般写在获取GetEnumerator函数中用于第一次重置光标位置

{

    private int index=-1;

    public CustomList()

        list = new int[] { 1,2,3,4,5,6,7,8 };

    public object Current

        get { return list[index]; }

    public IEnumerator GetEnumerator()
    {
        Reset();
        return this;
    }

    public bool MoveNext()
    {
        index++;
        return index < list.Length;
    }

    public void Reset()
    {
        index = -1;
    }
}

补充：集合与 GC

面试问到集合，真正想听的不是 API，而是“底层是什么、什么时候分配、什么时候回收”。这篇从数据结构讲到 GC，最后对比 Lua 的回收策略。

1. C#常见数据结构

数据结构类别存储方式有序性允许重复适用场景
**Array** (数组)基础连续内存是是存储数量固定、频繁随机访问的同类数据。
**List<T>**泛型集合连续内存是是最常用的动态列表，需要频繁按索引访问和末尾增删。
**LinkedList<T>**泛型集合不连续节点是是需要频繁在任意位置插入或删除，且很少按索引访问。
**Dictionary<TKey, TValue>**泛型集合哈希表否键唯一极速查找，通过唯一键快速取值，如用户ID查用户信息。
**HashSet<T>**泛型集合哈希表否元素唯一去重和快速判断存在性，如过滤重复关键词。
**SortedList/SortedDictionary**泛型集合有序树/表是（按键排序）键唯一需要始终按键排序存储，并能快速按范围查找。
**Stack<T>**泛型集合连续内存是是后进先出（LIFO） 场景，如函数调用、撤销操作。
**Queue<T>**泛型集合连续内存是是先进先出（FIFO） 场景，如消息队列、任务排队。
**ArrayList**非泛型连续内存是是旧代码兼容，存储object 类型，有装箱开销，新代码避免使用。

数组和List

List本质上是动态数组，具有总容量和存储的实际元素个数，连续存储，自动扩容，扩容机制是当前容量*2，整个过程中旧数组会被丢弃等待GC回收，

优点：可以用索引查找，cpu缓存友好。适用于按索引随机访问的，需要频繁按索引访问和末尾增删，

需要排序的

LinkedList（双向链表）

内部是一个双向链表，每一个元素都被包装成一个节点，只能直接访问链表的首尾，没有索引器只能从头或尾开始遍历，内存分布比较分散

适用于频繁的在头部插入或者删除元素，需要频繁在任意位置插入或删除（知道中间值的索引的情况下），且很少按索引访问。

Dictionary<TKey, TValue>

本质上是哈希表，不支持线程安全

  1. 计算哈希值：当你插入一个键值对时，Dictionary 会调用 key.GetHashCode() 获取一个整数哈希值。
  2. 映射到桶（Bucket）：哈希值会通过一个算法映射到内部数组的某个索引位置（称为“桶”）。
  3. 存储 Entry：键值对会存储在这个桶里。
  4. 查找：查找时，再次计算 Key 的哈希值，直接定位到对应的桶，然后在该桶内比较 Key 是否相等（通过 Equals 方法），找到后返回 Value。

哈希冲突：多个key的Hash值计算的值指向了同一个桶中造成了哈希冲突

解决办法：拉链法，用链表把同一个地址的元素串起来，一般采用头插法

核心思想：一个桶中可能调进来多个元素那就再桶里面挂一条“链”通常是链表，吧所有哈希到同一个同的元素串起来

工作原理：

插入时：

  1. 计算 Key 的哈希值，定位到对应的桶（Bucket）。
  2. 如果桶是空的，直接把新元素放进去。
  3. 如果桶里已经有元素了（发生冲突），就把新元素添加到这个桶的链表末尾（或头部）。

查找时：

  1. 计算 Key 的哈希值，定位到桶。
  2. 遍历这个桶里的链表，用 Equals 方法逐个比较 Key，找到匹配的就返回 Value。

删除时：

  1. 定位到桶。
  2. 遍历链表，找到匹配的 Key，从链表中移除该节点。
解决哈希冲突的其他方法对比
开放寻址法

线性探测：

  • 冲突了就往后挪+i，直到找到空位置，有点CPU缓存极其友好，连续地址，
  • 问题：整个区域聚集的元素堆积，查找效率急剧下降

二次探测：

  • 冲突了就往后挪+i*2二次方，跳跃式地寻找空位，
  • 能有效缓解线性探测的“主聚集”问题，但会产生相对较轻的二次聚集

双重哈希：

  • 当发生冲突时，使用第二个哈希函数来计算探测步长：step = hash2(key)，然后依次探测 index + step，index + 2_step，index + 3_step
  • 即使初始哈希位置相同，只要第二个哈希函数设计得好，它们的探测步长就不同，从而完全避免聚集现象

HashSet是专门存储唯一元素的集合，本质是只有一个Key、没有Value的字典

Dictionary主要是“通过Key快速查找Value”HashSet主要是“判断某个元素是否存在”，重复的值不会添加，会返回false

2. C#的GC和Lua的GC机制

C#的GC回收机制

C#的GC垃圾回收主要是为为大规模、高性能应用设计的

  • 核心算法是：分代回收，基于一个统计规律：大多数对象生命周期都很短，为此，将托管堆分成三代
  • 一个对象的代数，等于它已经成功存活的垃圾回收次数
    • 第 0 代 (Gen 0)：存放新对象，回收最频繁。
    • 第 1 代 (Gen 1)：存放存活过一次GC的对象。
    • 第 2 代 (Gen 2)：存放长期存活的对象，回收最少。
      这种设计让GC能集中精力高效清理“短命”对象，大幅提升整体内存管理效率
  • 回收过程
    一次完整的GC通常包含三个阶段：
    1. 标记 (Mark)：从根对象（如全局变量、局部变量）出发，标记所有可达对象。
    2. 清除 (Sweep)：回收未被标记的对象内存。
    3. 压缩 (Compact)：整理堆内存，消除碎片，为后续分配提供连续空间。

在GC过程中导致的卡顿是不是因为整理堆内存时，要把其他内存拷贝到新的位置上导致的

Lua的GC回收机制

lua的GC机制是一个轻量级的工具，Lua 的 GC 设计目标是在保证自动内存管理的同时，将对程序执行的干扰降到最低。

  • 核心算法是：三色增量标记-清除，为了避免一次性GC造成的长时间停顿，它将GC工作拆分为多个小的步骤，分散在程序中运行
  • 三色标记法过程：在增量过程中，通过三种颜色来追踪对象状态：
    • 白色 (White)：未被标记，若扫描结束仍为白色则被回收。（需要被回收的）
    • 灰色 (Gray)：已标记，但其引用的对象尚未被扫描。（没有查完，的待办事项）
    • 黑色 (Black)：已标记，且其所有引用对象也已被扫描（已经确保有被引用不需要被回收）

Lua 5.4 引入了分代GC（和C#类似）：
将对象分为年轻对象（刚创建的）和老年对象（活过好几次GC的）。
GC会只盯着年轻对象猛查，因为它们大概率会很快死掉（比如子弹、伤害数字）。对于老年对象（比如全局单例），GC减少扫描数量，极大减少了扫描工作量。

减少装箱GC的办法：

  • 优先使用泛型，List<>替代ArrayList，用Func代替非泛型委托
  • 用StringBulider处理字符串的加减

Gc的触发条件，Mono垃圾回收优化手段：

  • 运行过程中内存不足的情况
  • 手动调用：调用GC.Collect()（不推荐频繁调用），GC回收过程中会产生卡顿
  • 应用程序退出
  • 每帧结束后检查，达到阈值触发GC
  • 系统物理内存不足：强制触发GC

（1）减少对象创建（最核心）

  1. 对象池：复用频繁创建销毁的对象（如子弹、敌人、UI 元素）
  2. 值类型替代引用类型：对于小数据，使用 struct 替代 class，避免堆分配
  3. 复用数组和集合：提前分配足够大的数组，重复使用，避免频繁创建
  4. 避免字符串拼接：用StringBuilder或字符串插值替代+
  5. 避免装箱拆箱：
（2）减少 GC 扫描开销
  1. 及时释放引用：将不再使用的对象引用设为null，让 GC 尽早回收
  2. 禁用未使用的组件和 GameObject：避免不必要的对象存活
  3. 减少静态变量引用：静态变量是 GC 根对象，引用的对象永远不会被回收
（3）控制 GC 触发时机
  1. 手动控制 GC：在加载界面、关卡切换等不影响用户体验的时机手动调用GC.Collect()
  2. 设置 GC 阈值：通过GC.TryStartNoGCRegion()和GC.EndNoGCRegion()在关键帧禁止 GC

需要注意闭包问题

闭包：事件+Lambda表达式＋匿名函数时，会把外部变量的引用释放不了，需要取消订阅才可以释放
